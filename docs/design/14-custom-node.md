# 14. 직접 만든 노드 (Custom Node)

## 14.1 노드가 뭔가

**공장 라인의 기계 한 대**라고 보면 된다. 컨베이어로 물건이 들어오고, 뭔가 하고, 다음
기계로 내보낸다.

- `이미지 리사이즈` — 사진을 448×448로 줄이는 기계
- `모델 학습` — 데이터를 받아 모델을 만드는 기계
- `모델 추론` — 모델과 질문을 받아 답을 내는 기계

기계끼리 **규격이 맞아야** 붙는다. 컨베이어 폭이 다르면 물리적으로 안 붙듯이, "나는
사진을 내보낸다"와 "나는 글자를 받는다"는 연결되지 않는다. 편집기가 그 배선을 거부하는
것이 이 검사다(G1).

**Custom Node 는 당신 공정에만 필요한 기계를 직접 만들어 끼우는 것이다.** "이미지에서
나사 머리만 잘라낸다" 같은 기계는 우리가 안 만들었다 — 당신 도메인에만 필요하니까.

## 14.2 왜 규칙이 필요한가

남이 만든 기계를 라인에 끼우면 우리가 예상 못 한 방식으로 틀릴 수 있다. 그리고 이
분야의 기본 실패 방식은 **"틀리면 멈춘다"가 아니라 "틀린 채로 계속 돈다"** 이다.
학습은 정상적으로 돌고 손실 그래프도 예쁘게 내려가는데 모델만 이상해진다.

규칙은 그 조용한 실패를 **시끄럽게** 만들기 위해 있다. 느슨하게 하는 스위치는 없다 —
남의 노드가 우리 노드보다 덜 위험하지 않다.

## 14.3 세 걸음

### 1) 뼈대를 만든다

```
vlmt new-node my_nodes/crop.py --type my.crop_by_rule --kind processing --label "규칙으로 자르기"
```

노드 파일과 **그 노드의 테스트 파일**이 함께 나온다. 빈 파일부터 시작하면 대부분 한두
가지를 빠뜨리는데, 뼈대는 빠뜨릴 자리를 미리 채워 둔다.

`--kind` 는 셋 중 하나다.

| 종류 | 포트 모양 | 예 |
|---|---|---|
| `input` | 입력 없음, 출력 1개 이상 | 파일에서 사진을 읽어 온다 |
| `processing` | 입력·출력 각각 1개 이상 | 사진을 자른다 |
| `output` | 입력 1개 이상 | 결과를 파일로 쓴다 |

이 대응은 등록 시점에 강제된다(설계 02 §2.4). `input` 인데 입력 포트를 달면 임포트
자체가 실패한다.

### 2) 내용을 채운다

`examples/custom_node/pad_to_square.py` 가 실제로 도는 예제다. 사진을 정사각으로 채워
리사이즈가 가로세로를 눌러 버리지 않게 한다 — 정답에 화면 방향이 들어가는 우리 과제에서
실제로 필요한 기계다.

지켜야 하는 것은 넷뿐이다.

| | 규칙 | 안 지키면 |
|---|---|---|
| C3 | 파라미터는 **dataclass** | 앱이 설정 화면을 못 만든다. 화면에 아무것도 안 뜬다 |
| C4 | `input` 은 **`fingerprint()`** 를 구현한다 | 원본 파일이 바뀌어도 캐시가 옛 값을 돌려준다 |
| C2 | `processing` 은 **순수**하다 — 파일·네트워크·전역 난수·시계 금지 | 캐시가 거짓말을 한다. 같은 입력에 다른 답이 나오는데 캐시는 하나만 들고 있다 |
| C7 | 실패는 **`NodeError`** 로 던진다 | 한 샘플의 실패가 실행 전체를 죽인다 |

그리고 **구현은 파일 맨 바깥에 둔다.** 함수 안에 정의하면 Windows 에서 여러 프로세스를
쓸 때 그 기계를 못 찾는다. 등록 시점에 거부된다.

무작위가 필요하면 `ctx.rng()` 를 쓰고 `deterministic=False` 를 선언한다. 숨기지 말고
드러내면 캐시가 그것을 알고 처신한다.

`NodeError` 에는 네 가지를 담는다. 이 형식이 게이트를 유지시키는 장치다.

```python
raise NodeError(
    ctx.node_id,
    cause="HWC 3채널 이미지가 와야 하는데 모양이 (3, 480, 640) 다",
    hint=(
        "  안 잡혔다면: 채널이 뒤섞인 배열이 그대로 학습에 들어가고,\n"
        "  손실은 내려가는데 모델은 엉뚱한 것을 본다.\n"
        "  추정 낭비: 학습 시간 전부.\n"
        "  앞에 `adapt.image_layout` 을 넣어 HWC 로 맞춰라."
    ),
)
```

### 3) 검사하고 스펙에 적는다

```
vlmt check-node my_nodes.crop
```

등록 검사(`@register`)는 **선언**만 본다. 선언이 맞아도 틀릴 수 있는 셋을 여기서
실제로 돌려서 본다.

| 검사 | 왜 |
|---|---|
| 두 번 돌려 같은 값 | 순수한지는 선언으로 알 수 없다. 실제로 두 번 돌려야 안다 |
| 선언한 타입대로 내보낸다 | "Image 를 낸다"고 적어 두고 숫자를 내보내도 등록은 통과한다 |
| **다른 프로세스에서 임포트된다** | 등록 검사는 이름만 본다. 여기서는 진짜로 워커를 띄운다 |

표본 입력은 선언한 포트 타입에서 만든다. 만들 수 없는 타입이면 실행 검사를
**건너뛴다** — 지어낸 값으로 통과시키면 검사가 거짓말을 한다.

통과하면 스펙에 적는다.

```yaml
# project.yaml
node_modules: [my_nodes.crop]
```

**이 줄이 있어야 스펙이 자기완결적이다.** 없으면 세 가지가 깨진다.

1. `project.yaml` 만 받은 사람은 "노드를 찾을 수 없다"로 막히고, 무엇을 더 받아야
   하는지 파일 어디에도 없다
2. `editor.bat` 은 명령줄 플래그를 넘기지 않으므로 **앱 라이브러리에 그 상자가 안
   보인다** — 화면에서 끌어다 놓을 수가 없다
3. 어떤 구현으로 돌렸는지가 스펙에 남지 않는다

찾는 자리는 `project.yaml` 이 있는 폴더와 그 위의 과제(solution) 루트다.

## 14.4 캐시 — 가장 조용한 함정

캐시는 한 번 계산한 결과를 저장해 두고 다시 쓴다. 110장을 매번 다시 처리하면 시간이
아까우니까. 저장할 때 이름표를 붙이는데, 그 이름표에는 **노드 이름과 파라미터와 앞
기계에서 온 것**이 적힌다.

여기 없던 것이 있다. **기계 속을 고쳤는지 여부.**

내장 노드는 우리가 코드를 고칠 때 `ENGINE_ABI` 를 올려 캐시를 통째로 버린다. 남이 만든
노드에는 그 레버가 없다. 그래서:

> 코드를 고친다 → 다시 돌린다 → **결과가 안 변한다**

원인을 찾을 방법이 없다. 코드는 분명히 고쳤고, 프로그램은 정상 종료하고, 결과만 옛것이다.

그래서 **저장소 밖에서 온 노드는 등록 시점에 구현 소스를 해싱해 이름표에 같이 적는다**
(`NodeDef.impl_fingerprint`). 한 글자만 바뀌어도 이름표가 달라진다. 버전을 올리는 일을
사람의 기억에 맡기지 않는다. 옵트인 스위치가 아니다 — 켜는 것을 기다리면 잊는다.

`vlm_trainer.` 패키지 안에 두면 내장 노드로 취급되어 지문이 안 붙는다. **당신 노드를
거기 두지 마라.** `check-node` 가 이것을 본다.

물질화 재개(`--resume`)도 같은 함정이 있었다. `spec_hash` 는 그래프의 **모양**만 보므로
커스텀 노드 코드가 바뀐 것을 못 본다. 경계 상류 캐시 키를 모은 `bake_key` 를 저널에
남기고 재개할 때 비교한다 — 아니면 옛 코드로 구운 샘플과 새 코드로 구운 샘플이 한
학습에 섞인다.

## 14.5 하지 않기로 한 것

| 유혹 | 왜 안 되는가 |
|---|---|
| Custom Node 에만 게이트 완화 | `CLAUDE.md` 의 첫 번째 금지다. 남의 노드가 더 위험하지 덜 위험하지 않다 |
| YAML/JSON 으로 노드 정의 | 로직이 결국 파이썬이다. 설정 언어가 프로그래밍 언어가 되는 길 |
| 플러그인 매니페스트(`plugin.yaml`) | 설계 05 가 그렸지만 만들지 않았다. 파이썬 모듈 임포트로 충분하고, 매니페스트는 두 번째 진실의 출처가 된다 |
| Procedure 로 대체 | Procedure 는 **기존 노드의 조합**이다. 새 계산을 만들 수 없다 |

## 14.6 스펙이 파이썬을 임포트한다는 것

`node_modules` 는 스펙 파일이 파이썬 코드를 실행하게 만든다. 남의 `project.yaml` 을 여는
것이 남의 코드를 실행하는 일이라는 뜻이다.

이것은 노드 그래프 도구의 성질이지 우리가 새로 연 구멍이 아니다 — 명령줄 플래그로도
같은 일이 가능했다. 다만 **보이게** 해 둔다. 임포트 실패는 조용히 넘기지 않고, 어느
자리를 뒤졌는지까지 말한다. 넘기면 그다음 오류가 "노드를 찾을 수 없다"인데, 거기서는
무엇이 빠졌는지 안 나온다.
