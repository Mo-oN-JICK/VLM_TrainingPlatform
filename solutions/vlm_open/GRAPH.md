# 이 그래프가 하는 일

`editor.bat` 을 누르면 열리는 예제다. 사진과 질문을 받아 **VLM 을 파인튜닝하고,
학습한 모델이 검증 사진에 뭐라고 답하는지까지** 한 번에 본다.

상자 11개, 배선 23개, 깊이 10단. 위에서 아래로 흐른다.

---

## 과제

사진 한 장을 주고 두 가지를 맞히게 한다.

```
질문:  아래 사진을 보고 어떤 기계 요소인지 판정하고 이미지의 방향도 함께 적으시오.
사진:  (부품 사진 한 장)

정답:  <part_type>기어</part_type>
       <orientation>가로</orientation>
```

데이터는 110장이다 — 학습 100, 검증 10. Wikimedia Commons 에서 모은 **실물 사진**이고,
`part_type` 은 Commons 의 분류에서, `orientation` 은 파일의 가로세로에서 왔다.
지어낸 라벨은 없다.

---

## 상자 하나씩

### 들이는 것 (3개)

| 상자 | 하는 일 |
|---|---|
| **이미지 업로드** | `index.jsonl` 의 `image_path` 열을 따라 사진을 읽는다 |
| **메타데이터 업로드** | `question` · `part_type` · `orientation` · `split_hint` 네 열을 표로 읽는다 |
| **답변 형식 정하기** | `schemas/answer.yaml` 을 읽는다. 답을 어떤 칸으로 쓸지 정해 둔 것이다 |

### 다듬는 것 (3개 — 묶음 상자)

**이미지 전처리** — 사진을 448×448 로 맞춘다. 가로세로 비를 지키고 남는 자리는 채운다
(`keep_aspect` 를 켜 둔다). 모델은 고정 크기만 받고, 자원 예산 계산도 고정 크기를 요구한다.

**프롬프트 제작** — `{question}` 자리에 질문을 넣고, 사진이 들어갈 자리(`<image>`)를
**앞에** 붙인다. 모델에게 실제로 건네는 문장이 여기서 완성된다.

**검증 데이터 생성** — `part_type` 과 `orientation` 을 정답 형식대로 적고, 그 결과가
형식을 지키는지 검사한다. 어기면 그 샘플만 격리한다.

### 지키는 것 (1개)

**문제에 답이 섞였는지 검사** — 질문 안에 정답 낱말이 들어가 있는지 본다.

> 섞여 있으면 모델이 사진을 안 보고도 맞힌다. 검증 점수가 비현실적으로 높게 나오고
> 실험 전체가 무효가 되는데, **아무도 눈치채지 못한다.** 그래서 이 상자가 있다.

### 모으는 것 (1개)

**학습 데이터 맵핑** — 사진 + 질문 + 정답을 한 건으로 묶는다. 프롬프트의 `<image>`
개수와 실제 사진 수가 맞는지도 여기서 센다.

여기가 **사전 준비** 지점이다(점선 테두리). 여기까지는 미리 만들어 두고, 학습은 그
결과만 읽는다 — 그러지 않으면 사진 처리와 학습이 같은 GPU 를 두고 다툰다.

### 학습하고 확인하는 것 (3개)

**모델 학습** — `trainer.yaml` 을 따라 파인튜닝한다. 두 단계다.

| 단계 | 여는 것 | 왜 |
|---|---|---|
| `projector_align` | 프로젝터만 | 사진과 글을 잇는 다리부터 맞춘다 |
| `lora_ft` | 프로젝터 + LLM(LoRA) | 그 위에서 답하는 법을 익힌다 |

학습이 끝나면 **모델이 어디 있는지**를 내보낸다. 가중치를 값으로 흘려보내지 않는다 —
그러면 샘플마다 수 GB 가 복사된다.

**모델 추론** — 그 모델로 **검증 10장에만** 답을 만든다(`only_split` 이 `val`). 학습에 쓴
사진에 물으면 외운 것을 보게 된다.

**답변 결과 저장** — 답을 정답과 나란히 `runs/<id>/infer/answers.jsonl` 에 적는다.

> **채점하지 않는다.** 이 데이터는 라벨에 잡음이 있어서(아래 참고) 자동 채점 숫자가
> 나오면 그 숫자를 믿게 되는 쪽이 더 나쁘다. 사람이 읽고 판단할 일이다.

## 돌려 보기

```
editor.bat
```

툴바의 **`실행`** 을 누르면 준비 → 사전 준비 실행 → 학습 → 추론을 끝까지 간다.
터미널에서는 같은 일이 한 줄이다.

```
.venv\Scripts\python.exe -m vlm_trainer.cli.main pipeline ^
  solutions\vlm_open\projects\01_open\project.yaml --run-id t1
```

기본 백본은 `tiny-vlm` 이다 — 저장소에 들어 있어 **아무것도 내려받지 않고** 10초 안에
한 바퀴가 돈다. 답은 쓸 만하지 않다(0.00B 모델이다). 경로가 서는지 보는 용도다.

### 실물 모델로

```
... --set n_train.config_path=trainer_qwen2vl.yaml
```

`Qwen/Qwen2-VL-2B-Instruct` 로 바뀐다. **그래프는 한 글자도 안 고친다.**
가중치 4.4GB 를 먼저 받아야 한다:

```
.venv\Scripts\python.exe -m vlm_trainer.cli.main backbones --fetch hf:Qwen/Qwen2-VL-2B-Instruct
```

RTX 3060 12GB · 50 step 실측 — 학습 5분 22초, 추론 15초, **검증 10장 중 8장 완전 일치**.

## 왜 이렇게 생겼나

**질문 쪽과 정답 쪽이 따로 흐른다.** 중간에 `문제에 답이 섞였는지 검사` 가 둘을
마주 보게 한다. 한 줄로 흐르면 그 검사를 넣을 자리가 없다.

**사전 준비가 학습 바로 앞에 있다.** 사진 처리는 CPU 가, 학습은 GPU 가 한다. 섞어
놓으면 학습 중에 사진을 읽느라 GPU 가 논다.

**추론이 그래프 안에 있다.** 따로 돌리는 스크립트로 두면 "어떤 모델로 뭘 물었는지" 가
기록에 안 남는다. 여기 있으면 배선이 그것을 말해 준다.

**형식 검사가 두 번 나온다** — 정답을 만들 때(`검증 데이터 생성` 안), 그리고 묶을
때(`학습 데이터 맵핑`). 형식이 깨진 데이터가 학습에 들어가면 손실은 정상으로
내려가는데 답만 이상해진다.

---

## 이 데이터의 한계

**라벨에 잡음이 있다.** Commons 의 분류는 사람이 주제로 묶은 것이라, "Category:Rivets"
안에 리벳으로 고정한 칼집이 들어 있는 식이다. 수집기가 세 겹으로 거르지만(라이선스 /
제목에 부품 이름이 있는지 / 픽셀 통계로 사진인지 도면인지) 그래도 열에 두셋은 어긋난다.

**파이프라인을 시험하기에는 충분하지만 정확도를 재는 벤치마크로 쓸 물건은 아니다.**

## 고쳐 볼 만한 것

| 바꿀 곳 | 어떻게 |
|---|---|
| 사진 크기 | `이미지 전처리` 의 `size` |
| 질문 문장 | `프롬프트 제작` 의 `template` |
| 정답 항목 | `schemas/answer.yaml` 의 `steps` |
| 학습 길이 | `trainer.yaml` 의 `epochs` |
| 답 길이 | `모델 추론` 의 `max_new_tokens` |

상자를 눌러 오른쪽 패널에서 고친다. **타입이 안 맞는 배선은 놓이지 않는다** — 억지로
놓으면 왜 안 되는지 말해 준다.
